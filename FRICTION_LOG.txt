Maya interview coach — hackathon friction log
Updated October 23, 2026. Browser simulation; not a certified Alexa skill.

1. Task: start voice practice on a laptop.
Steps: open hosted Maya, start, allow the microphone, answer.
Expected: speech recognized. Actual: Maya spoke but could not hear.
Severity: critical.
Cause/workaround: the host Permissions-Policy denied microphone access;
changed only the coach page to microphone=(self), and separated permission,
device, service and network errors from genuine silence.
Suggestion: include permission/header checks in a voice-app readiness checklist.
Status: header and automated error paths verified; physical-device speech
validation remains separate from automated testing.

2. Task: start practice on a slow connection.
Steps: tap Start repeatedly while waiting.
Expected: one conversation. Actual: overlapping audio.
Severity: high.
Workaround: disable Start during launch; use one cancellable audio channel.
Suggestion: provide a reference single-flight voice state machine.
Status: queue/cancellation tests pass; continue real-device validation.

3. Task: hear detailed feedback.
Steps: answer, then request feedback.
Expected: complete guidance and a retry invitation.
Actual: clipped/topic-only feedback and abrupt handoffs.
Severity: high.
Workaround: fuller rubric coaching and serial TTS segments with cancellation.
Suggestion: document long-response speech handling and accessible progress cues.
Status: fuller feedback and complete sequential audio implemented/tested.

4. Task: add live model-generated interview questions and feedback.
Steps: initially configure the optional Bedrock feedback path and exercise
hosted feedback; subsequently test the isolated Surprise me round end to end.
Expected: an actual model response. Initial actual result: labelled rubric
fallback, showing that configuration alone did not prove successful inference.
Severity: high for demonstrating the intended AI feature.
Resolution: preserve regular rubric coaching and isolate generative AI in
surprise_question and evaluate_surprise MCP tools using Bedrock Converse and
Meta Llama. Verify a generated question, feedback on an answer, and return to
the same regular practice question through the deployed service/browser flow.
Status: optional bonus-round inference verified October 22. This does not
claim that the legacy regular-feedback adapter or every device was validated.
Safeguards: server-side credentials, bounded inputs, structured-output checks,
timeouts and session/process limits; regular practice remains available on error.
Suggestion: provide an onboarding diagnostic that confirms a real invocation,
distinguishes credentials, region/model access and response-format failures,
and exposes a clear failure state to the learner instead of silent waiting.

5. Task: give a longer spoken interview answer.
Steps: start voice practice, hear a question, and speak a detailed answer.
Expected: Maya waits until the learner finishes before giving feedback.
Actual: a user reported recognition ending early and feedback starting on a
partial answer. This is a browser-recognition finding, not an Alexa-device test.
Severity: high; interruptions prevent learners from completing their reasoning.
Current workaround: typed input for dependable review of long answers.
Proposed improvement: explicit finished/continue handoffs, spoken acknowledgement
of pauses, and recovery that preserves the answer rather than evaluating early.
Suggestion: publish an accessible long-answer conversation reference covering
recognition end events, pauses, interruptions, retry and silence recovery.
Status: unresolved; proposed handoffs are not claimed as shipped. Validate on
physical phones and laptops with learners before marking this resolved.

Items 1-3 are our browser/hosting integration findings, not alleged Amazon
device defects. MCP supports explicit coaching-tool boundaries. The project
uses the Alexa+ web-simulation route; public Alexa distribution is separate.
